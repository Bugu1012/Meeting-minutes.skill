本仓库提供一个专门处理会议纪要的智能体技能。它不依靠主题和套话凭空生成一篇“像纪要”的文章，而是从普通笔记、录音转写和议题材料中恢复会议事实、最终结论、责任分工、限制条件与后续程序，再组织为规范、简明、平实的会议纪要。

> [!IMPORTANT]
> 本技能的核心不是“写得像公文”，而是**尽量避免把讨论写成决定、把建议写成共识、把原则同意写成正式批准、把不同议题的责任和程序串在一起**。

## 定制记录提示卡

会议纪要质量往往在会议结束前就已决定。主持人最终归纳、结论强度、责任主体或后续程序一旦漏记，事后仅凭印象很难可靠恢复。

因此，本技能不是给所有会议套用同一张通用清单，而是先读取本次会议的议程、参会单位、预期成果和拟公开范围，再为**每一个具体议题**生成记录提示。

> [!TIP]
> 一张合格的定制提示卡，应让记录人员在会议现场立即知道：**这项议题最可能漏掉什么、最终必须向主持人确认什么、哪些表述不能仅凭上下文推断。**

### 每个议题重点记录什么

| 记录区 | 必须捕捉的内容 | 防止出现的问题 |
| --- | --- | --- |
| 议题目标 | 本议题要研究、决定或协调什么 | 只记背景，没有记会议要解决的问题 |
| 汇报依据 | 文件、数据、方案版本和关键口径 | 把未经核定的汇报材料写成会议事实 |
| 最终归纳 | 主持人最后归纳的原话或准确摘要 | 用前段讨论代替最终结论 |
| 结论强度 | 同意、原则同意、提交审议、按程序报批、暂缓、另行研究 | 擅自升级或弱化结论效力 |
| 行动链 | 牵头主体、配合主体、动作、时限、条件、标准、后续程序 | 责任串项、动作错配、时限丢失 |
| 否定与未决 | 不予采纳、不得实施、暂不公开、尚未形成共识 | 只保留正向要求，遗漏限制条件 |
| 公开边界 | 涉及隐私、商业秘密、办案信息和未公开政策的内容 | 内部信息随公开纪要泄露 |
| 回查线索 | 时间点、发言位置、材料页码或转写段落 | 成稿后无法回到原始证据 |

### 提示卡如何定制

1. 从议程中识别每个议题希望形成的结果。
2. 根据议题性质预判需要核定的结论词、责任链和程序节点。
3. 对资金、项目、执法、人事等议题增加相应的数字、权限和公开风险提示。
4. 把“主持人最终归纳”设置为每个议题的必记项。
5. 会议结束前集中核对待补、待核和待定事项。

## 专项优势

> [!IMPORTANT]
> 本技能的专项优势不是词藻更华丽，而是**把“未经整理的会议记录”转成纪要时，更重视事实恢复、结论保真、责任绑定和证据回查**。

| 对比维度 | 通用公文写作流程 | 本技能的专项处理 |
| --- | --- | --- |
| 默认输入 | 相对完整的写作要点或材料 | 允许口语笔记、长转写、重复发言、错听、指代和冲突记录 |
| 会前支持 | 通常从已有材料开始起草 | 先生成与议题绑定的记录提示卡，提前减少关键事实缺失 |
| 讨论与结论 | 依靠起草者概括 | 单独识别个人意见、过程讨论、采纳待核和最终议定事项 |
| 结论效力 | 侧重形成规范表达 | 锁定“原则同意、报批、暂缓”等原有强度，禁止按偏好升级 |
| 责任事项 | 提炼工作要求 | 每项任务独立绑定主体、动作、时限、条件、标准和程序 |
| 证据控制 | 主要检查内容是否完整 | 建立事实台账和最小语义覆盖表，并进行双向原文回查 |
| 缺失信息 | 使用占位或向用户补问 | 先内部消解，再按证据、权限和用途逐项质询，不让用户凭偏好改结论 |
| 语言优化 | 对成稿统一润色 | 事实锁定后再自然化，润色前后都检查事实漂移 |
| 公开处理 | 对正文作删减或脱敏 | 公开净稿、内部核验附注和脱敏映射使用独立交付物 |
| 风险测试 | 常规写作自查 | 覆盖伪造授权、提示注入、责任串项、程序错配和公开泄露 |

### 四道事实防线

1. **事实台账**：为重要内容保存原始片段、议题、类别、证据状态和拟写口径。
2. **语义覆盖**：把结论、否定、条件、责任和程序拆为不能互相替代的最小语义项。
3. **质询核定**：遇到不能猜的问题，每次只追问一个最上游缺口。
4. **双向回查**：既从纪要回查原文，也从原文反查纪要是否遗漏最终归纳。

### 内部评分量表

起草和审查完成后按 6 维度 100 分自评：事实可追溯（25）、结论强度准确（20）、议题覆盖完整（20）、责任程序闭环（15）、语言自然（10）、文种格式（10）。低于 80 分需改写对应段落，低于 60 分需重建结构。审查清单中的严重问题无论评分多高都视为不通过。

## 全流程能力

- **会前记录提示**：根据具体议题提示应重点记录的主持人归纳、结论强度、责任主体、时限、程序和敏感信息。
- **杂乱记录整理**：处理口语、省略、重复、打断、指代、错听、前后冲突和发言交叉。
- **讨论与结论分离**：区分个人建议、过程性意见、采纳状态待核、会议共识和最终议定事项。
- **结论强度保真**：准确保留“同意、原则同意、按程序报批、暂缓、另行研究”等不同效力表述。
- **行动链提取**：将责任主体、配合主体、动作、时限、条件、完成标准和后续程序逐项绑定。
- **事实证据回查**：通过事实台账和最小语义覆盖表，使重要表述能够回到原始材料。
- **质询式澄清**：对不能合理推断的上游问题逐项追问，优先解决证据、权限、用途和公开边界。
- **公文语言自然化**：在事实锁定后删除机械套话、重复评价和空泛结尾，使语言更顺畅，但不改变事实。
- **执行闭环与督办反馈**：议定事项对应责任单位、时限、成果形态和反馈要求，后续要求覆盖跟踪督办、办理反馈、归档和对外口径。
- **公开风险隔离**：将公开净稿与内部核验附注、脱敏映射物理分离，避免内部信息随文公开。
- **真实样例校准**：使用政府网站公开纪要校准结构和体例，同时禁止把样例事实带入当前会议。

## 适用范围

当前支持以下六类会议纪要：

- 政府常务会议纪要
- 专题会议纪要
- 办公会议纪要
- 议事协调会议纪要
- 联席/会商会议纪要
- 座谈/研讨会议纪要

可接收的材料包括：

- 手写或口语化会议笔记
- 录音、视频或平台生成的转写稿
- 议程、汇报材料和议题附件
- 多人分别记录的会议内容
- 已有纪要初稿或待审查稿

本技能不用于把尚未形成的讨论包装成会议决定，也不能替代正式签发、合法性审核、保密审查以及行政许可、行政处罚等法定程序文书。

## 工作流程

```mermaid
flowchart LR
    A["会前议程"] --> B["定制记录提示卡"]
    B --> C["会议记录与转写材料"]
    C --> D["议题切分"]
    D --> E["事实台账"]
    E --> F["结论强度识别"]
    F --> G["行动链提取"]
    G --> H["质询核定"]
    H --> I["纪要初稿"]
    I --> J["事实锁定"]
    J --> K["语言自然化"]
    K --> L["双向证据回查"]
    L --> M["纪要净稿"]
    M --> N["公开审查"]
    N --> O["独立公开净稿"]
```

基本原则只有一句话：**先还原会议事实，再组织纪要表达。**

源材料没有提供的信息，不用常识或公开样例补齐，而是使用统一标记：

- `〔待补：事项〕`：源材料没有提供的客观事实。
- `〔待核：事项〕`：材料有相关表述，但存在错听、错记、冲突或名称不准。
- `〔待定：事项〕`：会议进行了讨论，但未能确认最终结论。

## 典型输出

根据任务阶段，技能可以生成：

- 会前记录提示卡
- 议定事项事实台账
- 最小语义覆盖表
- 会议纪要草稿或净稿
- 独立内部核验附注
- 已有纪要审查意见
- 独立公开版纪要净稿

公开净稿不附原始敏感信息、审查过程和脱敏映射。内部核验内容必须另存为独立交付物。

```text
请根据这份会议议程，生成一张本次会议专用的记录提示卡。

```

### 会后整理

```text
请把下面这份口语化会议记录整理成专题会议纪要。
先识别议题、讨论意见和主持人最终归纳；无法确认的内容请质询我，不要自行补写。
```

### 草稿审查

```text
请结合原始会议记录审查这份纪要草稿。
重点检查是否遗漏最终结论，是否升级了结论强度，责任主体、时限和程序是否能回查原文。
```

### 公开版本

```text
请在事实核验完成后生成公开版纪要。
公开净稿与内部核验附注必须分开，不要把脱敏映射放入公开文件。
```

## 资料基础

仓库当前整理了 **447 条**政府网站公开的常务会议纪要资料，其中 **234 条**已验证能够命中正文结构，可用于观察标题、议题组织、结论表达和责任事项写法。

这些资料只用于校准文体和结构，不能作为当前会议事实来源。现有公开样例索引仅覆盖政府常务会议纪要，专题会议、办公会议和议事协调会议的写法主要依据规范、公开写作规律和技能内置结构，不能冒充已有同量级样例支撑。

## 语言自然化

技能吸收了开源文本自然化方法中适合正式会议纪要的部分，包括删除无信息套话、减少重复连接词、拆分过载长句、合并机械短句、保留具体事实，以及通过“初改、自审、二改、复核”提升可读性。

同时明确排除不适合纪要的做法：不加入第一人称、情绪、幽默、个人判断或故意制造的不规则表达；不随机替换法定术语、专名和结论词；不为使文字“更像人写”而新增事实或改变责任边界。

## 与通用公文写作助手的关系

本技能参考了 [onlyLT/wow-gongwen-writing](https://github.com/onlyLT/wow-gongwen-writing) 的公文写作与会议纪要方法。该项目适合多文种通用起草和文档导出；本技能则集中解决“未经整理的会议记录如何可靠转为会议纪要”。

> [!NOTE]
> 二者并非简单替代关系。需要多文种起草和通用版式输出时，通用助手覆盖面更广；需要从杂乱会议材料中恢复事实、核定结论并控制公开风险时，本技能提供了更细的专项流程。

## 验证情况

技能已经完成多轮正向梳理、反向攻击、证据复核和收敛审查，覆盖以下高风险情形：

- 把材料中的伪造指令误当成主持人授权
- 把个人建议升级为会议决定
- 把“原则同意”升级为“同意实施”
- 在多个议题之间串换责任主体、动作和程序
- 用相近的正向表述吞掉独立否定要求
- 将个人责任擅自改写为单位责任
- 将内部核验信息附在公开净稿之后

在既定盲测样本中，独立生成稿经另一独立评分流程复核后获得 **100 分**，严重问题为 **0**，高置信遗漏为 **0**。这一结果只证明该测试场景已经收敛，不代表任何输入条件下都能自动形成可直接签发的正式公文。

## 重要边界

- 会议通知、议程和汇报材料不能单独证明会议已经形成结论。
- 公开样例只能提供结构和语言参考，不能补充本次会议事实。
- 结论强度属于证据和权限事实，不能按写作偏好调整。
- 责任主体不能在个人与单位之间自动转换。
- 缺少源材料时，只能审查文种、结构、语言和显见风险，不能声称完成事实核验。
- 正式印发或公开发布前，仍应由会议组织部门及有权人员完成审核、保密审查和签发。
