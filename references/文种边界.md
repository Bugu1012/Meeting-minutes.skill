# 文种边界

## 纪要的文种定位

纪要用于记载会议主要情况和议定事项。它的核心不是“发布命令”，不是“请求批准”，也不是“完整记录每个人说了什么”，而是把会议形成的主要意见、原则结论、责任分工和后续要求写成可追踪、可办理的公文材料。

会议记录、录音转写稿和口语化笔记是纪要的源材料，不是纪要本身。只有经过议题切分、事实核对、结论识别和责任绑定后，才能转为纪要。

依据定位见 `规范依据.md`。涉及正式印发、公开发布、涉密管理或程序替代风险时，应同时核对现行公文处理规则和本机关制度。

## 适用边界

适合使用纪要的情形：

- 会议已经召开，需要记录会议主要情况。
- 会议已经形成明确议定事项。
- 多个单位需要按照会议形成的意见分工办理。
- 需要留痕会议对某个方案、事项、工作安排的研究过程和原则意见。
- 需要公开会议审议事项、主要要求和落实方向。
- 需要把杂乱会议记录提炼为经过证据回查的纪要草稿。

## 不适用边界

不适合使用纪要的情形：

- 需要上级批准事项：用请示。
- 需要向上级汇报情况：用报告。
- 需要正式部署工作：用通知。
- 需要作出具有独立效力的行政决定：用决定、批复、行政许可文书或其他法定文书。
- 需要逐字保存发言内容：用会议记录。
- 需要发布政策规范：按规范性文件程序另行制文。

## 与相近文种的区别

| 相近材料 | 主要区别 |
|---|---|
| 会议记录 | 会议记录偏原始、完整、过程性；纪要偏提炼、结论性、办理性。 |
| 通知 | 通知用于部署、告知、转发；纪要用于记录会议议定事项。 |
| 报告 | 报告向上级汇报工作；纪要记录会议内部或一定范围内的议定事项。 |
| 请示 | 请示向上级请求批准；纪要不得使用“妥否，请批示”等请求语。 |
| 决定 | 决定直接作出重大安排或奖惩；纪要不能擅自替代决定。 |
| 批复 | 批复答复下级请示；纪要不能替代批复。 |

## 行文方向

纪要一般面向本机关内部、有关单位或公开社会公众。写作时要先判断版本：

- 内部办理版：可以保留更多责任分工、办理时限和协调机制，但仍要避免无关过程细节。
- 公开发布版：保留会议时间、主持、议题、主要意见和落实要求，删去内部争议、敏感过程和不宜公开事项。
- 协调落实版：突出牵头单位、配合单位、办理路径和反馈机制。

纪要发送有关单位知悉或办理时，仍应保持“会议议定”口径；如需直接部署工作，应另行制发通知或其他相应文种。

## 判断问题

起草前先回答：

- 是否有真实会议？
- 是否已有明确议定事项？
- 是否只是会议通知或会议新闻？
- 是否需要上级批准？
- 是否会替代正式审批或法定文书？
- 是否准备公开发布？

如果答案显示“没有会议”“没有议定事项”“需要请求批准”“需要正式部署”，不要直接写纪要。

会议已经召开但某个议题没有形成结论时，可以在纪要中如实写“会议研究了有关事项，要求进一步论证”或“该事项暂未形成结论”，不能为了完整而虚构议定事项。
