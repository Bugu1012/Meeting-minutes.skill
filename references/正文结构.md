# 正文结构

正文结构服务于事实，不反过来支配事实。普通会议记录中没有“认为、指出、强调、要求”的完整层次时，只保留材料实际支持的层次。

## 标题公式

常用标题：

- `机关名称 + 第〔序号〕次常务会议纪要`
- `机关名称 + 年度第〔序号〕次常务会议纪要`
- `关于 + 事项名称 + 专题会议纪要`
- `事项名称 + 协调会议纪要`
- `机关名称 + 办公会议纪要`
- `会议名称 + 纪要`

标题禁忌：

- 不写成“关于印发会议纪要的通知”，除非另有通知正文。
- 不写成“会议情况报告”。
- 不写成“会议决定”，除非文种确为决定。

## 常务会议纪要结构

常务会议纪要通常采用“会议基本情况 + 议题分项 + 议定意见”的结构。

```
〔年月日〕，〔主持人〕在〔地点〕主持召开〔机关名称〕第〔序号〕次常务会议，听取、审议、研究、传达学习了〔议题概述〕。现纪要如下：

一、会议听取了〔事项〕情况的汇报
会议原则同意〔结论〕，由〔牵头单位〕牵头，〔配合单位〕配合，根据会议讨论意见〔后续程序〕。
会议指出，〔判断〕。
会议强调，〔重点〕。
会议要求，〔要求〕。
```

适用特点：

- 多议题并列。
- 每个议题可独立成项。
- 常见动词为“听取、审议、研究、传达学习”。
- 常见结论为“原则同意、按程序报批、修改完善后实施”。
- 由普通记录整理时，每个议题优先交代最终状态，再写必要的判断和要求，便于核对议定事项。

公开常务会议纪要若材料提供尾部要素，可在正文议题后写：

```
出席：〔出席人员或范围〕

列席：〔列席人员或范围〕

记录：〔记录人〕

〔整理机关〕整理

〔整理日期〕

〔公开属性〕
```

材料未提供的尾部要素不得臆造；材料已提供的记录、整理机关、整理日期和公开属性，不应误列为未验证项。

## 专题会议纪要结构

专题会议纪要通常围绕一个事项展开。

```
〔年月日〕，〔主持人〕在〔地点〕主持召开〔事项名称〕专题会议，研究〔事项〕有关问题。现纪要如下：

一、会议基本意见
会议认为，〔背景和判断〕。

二、议定事项
会议原则同意〔事项〕。
会议明确〔具体安排〕。

三、责任分工
由〔牵头单位〕牵头，〔配合单位〕配合，于〔时限〕前完成〔任务〕。
```

适用特点：

- 事项单一。
- 背景、争议、协调意见更重要。
- 要明确责任分工和时间要求。
- 争议过程一般不写，但最终未解决的分歧、暂缓事项和后续论证安排不能被删掉。

## 办公会议纪要结构

办公会议纪要偏内部协调和日常管理。

```
〔年月日〕，〔主持人〕主持召开办公会议，研究〔事项〕。纪要如下：

一、关于〔事项一〕
会议明确，〔办理意见〕。

二、关于〔事项二〕
会议要求，〔办理要求〕。
```

适用特点：

- 篇幅宜短。
- 少写宏观判断，多写办理事项。
- 可突出责任人、责任处室、完成时限。

## 议事协调会议纪要结构

议事协调会议纪要用于跨单位、跨部门协调事项。

```
〔年月日〕，〔主持人〕主持召开〔事项名称〕协调会议，研究协调〔问题〕。现纪要如下：

一、会议形成的基本意见
〔总体判断和处理原则〕。

二、任务分工
〔单位一〕负责〔任务〕。
〔单位二〕配合〔任务〕。

三、后续机制
建立〔协调、反馈、督办、验收〕机制。
```

适用特点：

- 分工要清楚。
- 协调机制要落地。
- 不宜把协调意见写成已经完成法定审批。

## 联席/会商会议纪要结构

联席/会商会议纪要用于多部门、多单位共同研究协同事项。

```
〔年月日〕，〔主持人〕主持召开〔事项名称〕联席会议，研究协调〔问题〕。〔参会单位一〕、〔参会单位二〕、〔参会单位三〕等有关单位负责同志参加会议。现纪要如下：

一、会议形成的基本意见
〔各方共识和处理原则〕。

二、职责分工
〔单位一〕负责〔任务〕，于〔时限〕前完成。
〔单位二〕负责〔任务〕，〔单位三〕配合。

三、配合机制与时间节点
建立〔协调、信息通报、联合督办〕机制，〔频次〕召开调度会议。

四、后续要求
由〔牵头单位〕负责跟踪督办，于〔时限〕前将办理情况报〔报送对象〕。
```

适用特点：

- 标题常见"〔事项〕联席会议纪要""〔事项〕协调会议纪要""〔事项〕会商会议纪要"。
- 开头宜先写参会单位和会商事项。
- 正文重在各方共识、职责边界、配合机制和时间节点。
- 责任分工要写到具体单位，不能只写"各有关单位"。
- 不宜把协调意见写成已经完成法定审批。

## 座谈/研讨会议纪要结构

座谈/研讨会议纪要用于调研座谈、征求意见、专题研讨等场景。

```
〔年月日〕，〔主持人〕在〔地点〕主持召开〔事项名称〕座谈会，听取〔对象〕关于〔主题〕的意见建议。〔参加范围〕共〔人数〕人参加座谈。现纪要如下：

一、座谈讨论情况
与会人员围绕〔主题〕进行了讨论，主要意见如下：
〔归纳各方意见〕。

二、会议形成的基本共识
〔提炼共识〕。

三、后续安排
〔明确后续研究方向、征求意见安排或上会计划〕。
```

适用特点：

- 标题常见"〔事项〕座谈会纪要""〔事项〕研讨会议纪要"。
- 开头宜先写会议背景、参加范围和讨论主题。
- 正文重在归纳意见、提炼共识、明确后续研究方向。
- 不宜误写成已经形成刚性决定的执行纪要。
- 未形成一致意见的事项，写"继续研究""进一步征求意见"，不写成"会议决定"。

## 类型选择警告

起草纪要前，应先判断属于哪一种类型，再决定标题写法、开头句式和正文重心：

- 不能把座谈会纪要写成常务会议纪要。
- 不能把专题协调纪要写成纯记录式流水账。
- 不能把联席/会商纪要写成单一部门的办公会议纪要。
- 标题写"专题会议纪要"，正文就应围绕单一专题集中展开；标题写"常务会议纪要"或"办公会议纪要"，正文就应允许多议题并行，但仍需按议题分层组织。

## 层级规则

- 一级标题用于会议议题。
- 二级层次用于同一议题下的具体要求。
- 同一层级句式保持一致。
- 一项议题内不要混入无关议题。
- 责任分工最好紧跟对应议题，不要集中堆在结尾导致责任不清。
- 同一议题中的责任、时限、标准和程序应与具体动作绑定，不能只列单位名单。
- 不为追求形式整齐给所有议题机械套用相同数量的小点。
- 正式印发稿的发文字号、期号、主送范围、印章和印发机关等版式项目，按本机关制度和现行公文格式规则处理；不要因套模板强行补不存在的项目。
- 本次会议的原始材料或用户明确交付的本次会议正式页面已有文件编号、发布日期、记录、整理机关、整理日期、公开属性等元数据时，应纳入标题下方、尾部或核验判断；用于体例参考的公开样例不得提供本次会议元数据。
