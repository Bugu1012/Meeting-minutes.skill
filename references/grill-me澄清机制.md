# grill-me澄清机制

本文件用于在纪要起草、审查、改写中处理“不清楚但不能猜”的问题。原则是：事实先查，证据、权限和用途再问；每次只问一个上游问题，并给出保守处理建议。

会前沟通也使用本机制，但目的不同：只确认会改变记录重点的预期成果、重点议题和纪要用途，随后立即生成定制提示卡。

## 一、先区分事实和决策

事实问题能从本次会议记录、附件、经核定的议定事项清单或上下文中查到时，先自行核对，不问使用者。真实公开样例索引和用于体例校准的公开页面只能帮助判断结构和表达习惯，不能用于补核本次会议的时间、人员、议题、结论、责任和程序。用户明确把本次会议的正式公开页面作为源材料交付时，应登记为用户提供的本次会议材料，不得再把它当作普通样例迁移事实。

常见事实问题：

- 会议名称、会议时间、主持人、议题。
- 文件编号、发布日期、整理机关、整理日期、公开属性。
- 材料中已经写明的牵头单位、配合单位、办理时限、后续程序。

证据、权限和用途问题不能替使用者决定，应使用 grill-me 逐问确认。

常见问题：

- 是否按纪要处理，还是改用通知、请示、报告、批复、决定或函。
- 是否生成公开发布稿、内部办理稿、摘要稿或正式印发稿。
- 是否保留内部争议、个人表态、项目细节、资金安排、企业信息、案件信息。
- 是否在事实不足时继续生成草稿，还是先补材料。
- 是否有主持人归纳、议定事项清单、核定稿或其他有权材料证明某项结论强度。

结论强度不是写作偏好。不得询问使用者“是否可以把原则同意写成同意实施”。应询问是否存在能够证明准确结论词和程序路径的核定依据。没有依据时保留较低强度原词，或标为〔待核〕，不得升级。

## 二、必须触发 grill-me 的情形

以下问题会影响文种、安全、程序或结论强度，不得直接猜：

- 无法确认是否真实召开会议。
- 无法确认会议是否形成议定事项。
- 材料同时像会议记录、通知、请示、报告或决定，文种边界不清。
- 用户要求“正式定稿”或“公开发布”，但公开属性、密级、保密审查、公开审查不清。
- 用户要求公开、外发、正式印发或扩大流转范围，而材料含个人隐私、商业秘密、执法办案、未公开政策、内部争议或涉密线索。
- 责任单位、办理时限、后续程序缺失，但用户要求形成可执行正式稿。
- 结论强度不清，可能把“研究、原则同意、按程序报批”误写成“决定、批准、实施”。

## 三、可以不中断的情形

以下缺口不必立即打断使用者，可按性质使用〔待补〕、〔待核〕、〔待定〕或列入未验证项：

- 会议地点未提供，但不影响草稿安全。
- 文号、期号、印发范围未提供，且用户只要草稿。
- 出席、列席名单未提供，且正文可以不列。
- 个别日期、数字、名称需要后续核对，但不影响文种和程序判断。
- 用户明确要求先出草稿，且缺失信息不会导致公开风险或程序替代风险。

## 四、提问格式

使用 grill-me 时，按以下格式输出：

```
〔质询式澄清〕
依据：当前缺口属于使用者掌握但材料未给出的决策信息。
处理：先确认最上游决策，再继续起草或审查。

问题：〔一次只问一个问题〕
推荐答案：〔给出我的推荐答案和理由〕
确认后我将：〔说明下一步如何处理〕
```

## 五、常用问题

会前目标不清时：

```
问题：本次会议最需要形成并在纪要中留痕的结果是什么？我的推荐判断是先按“明确议题结论、责任分工和后续程序”准备记录提示；如果本次只听取情况、不作决定，我会改为突出主要判断和后续研究事项。你确认哪一种？
```

会前公开边界不清时：

```
问题：本次记录主要用于内部办理还是准备公开发布？我的推荐答案是先按内部记录准备，因为公开属性尚未明确；提示卡会单独标出不宜公开的信息。你确认吗？
```

文种边界不清时：

```
问题：这份材料是否已经有正式会议并形成议定事项？我的推荐判断是：如果只是部署工作，应改用通知；如果已经开会并要记录议定事项，才继续写纪要。你确认按纪要处理吗？
```

公开属性不清时：

```
问题：这份纪要是内部办理稿还是公开发布稿？我的推荐答案是先按内部审阅稿处理，因为材料中公开属性未明确，避免误删或误公开敏感内容。你确认吗？
```

结论强度不清时：

```
问题：是否有主持人最终归纳、议定事项清单或会议组织部门核定稿，能够证明材料里的准确结论词和后续程序？当前证据只支持“原则同意，按程序办理”，我的建议是保留这一较低强度口径；如有核定材料，请提供对应片段或说明核定依据。
```

事实不足但用户要定稿时：

```
问题：当前缺少〔关键事实〕，会影响正式印发。我的推荐答案是先生成“草稿并列未验证项”，不标记为定稿。你确认按草稿处理吗？
```

## 六、问完后的处理

- 使用者提供可定位的核定材料后，把有证据支持的内容写入正文或审查结论。
- 使用者仅作口头选择、未提供结论依据时，可以把该信息记为补充说明用于草稿核对，但不得据此升级结论、宣称完成官方核定或生成最终公开稿。
- 会前确认后，按议题生成记录提示卡，不继续追问可用占位符处理的细节。
- 用户不确认时，停止定稿，输出缺口清单和可继续路径。
- 用户只要求先出草稿时，保留〔待补〕、〔待核〕或〔待定〕并在未验证项中列出。
- 不把 grill-me 问答原文写入正式纪要；只吸收被确认的事实或决策。
- 非阻塞缺口通常不超过两轮质询；两轮后先输出带统一标记的草稿或提示卡。涉及文种、权限、公开安全或结论强度的阻塞问题，应继续每次只问一个问题，直到阻塞项解决，或者停止定稿并输出缺口说明。
